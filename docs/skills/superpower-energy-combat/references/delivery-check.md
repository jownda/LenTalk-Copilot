# 交付检查

生成前实际读取主文件、招式库、能量库、运镜库和中文写法。检查失败只修对应问题，不凭感觉宣称已经执行 Skill。

## 时序与来源

1. 打斗逐 0.5s 列格，连续、无空缺/重叠且总长正确；15s 纯打斗必须 30 格，只有非整倍数末格可不足 0.5s。
2. 剧情/对白每 2–3s 一块，混合内容分别按类型规划，末段不足照实标注。
3. 每个攻击/防守动作引用招式库 ID 与原词；每个能量动作引用能量库 ID 与原词；每镜景别、运镜引用运镜库 ID 与原词。库外变体明确标记，不虚构来源。
4. 规划保留原词与映射；成品以可见动作/路径为主，名称按需保留。去掉名称后仍应能辨别动作，不能只堆术语或自造运镜名。
5. 用户要完整提示词时，输出仍保留全部半秒动作格；用户只要成品时，内部完成引用检查，去掉文件路径和 ID。

## 超能底线（三条，最高优先级）

6. **力有来源**：每次腾空、变向、加速、隔空牵引，是否写出支点/推进/蓄能/代价中的至少两样？有没有「他是超人所以可以」这类无来源写法？
7. **先接触后特效**：命中是否先于火星、闪光、震屏、音效、破坏？有没有「光一亮，远处同时爆炸」？
8. **破坏只增不减**：已碎的墙是否在后续镜头里保持碎？断口、焦痕、坑洞是否持续到结尾？

## 发力与打击感

9. 每次重击是否能找出「支点 → 传力 → 末端 → 反作用」四段中的三段？
10. 每次命中是否具备三件套：接触帧可读（2–3 帧）+ 后果持续（0.3–0.5 秒）+ 攻击者反作用？
11. 是否只有被打的人在动、打的人一动不动？有则补反作用。
12. 能量链是否写了起点、可见路径、末端成形？末端形态是否与接触效果一致（面推、点穿、线切）？
13. 隔空力程是否写了介质先动的过程？有没有抬手即命中？
14. 击退前是否做过空场检查（起点、方向、距离、落点、障碍）？起点与落点是否重合？
15. 位移尺度是否由小到大递进？有没有第一击就飞出十米？

## 能量与能力

16. 能量六阶段（聚能、引导、传播、相遇/命中、响应、消散）是否齐全？缺的能否补因果而不是删阶段？
17. 束流是否写了束径与落点行为？弹体是否有飞行过程与至少一次落空？场域是否写了边界、内部反应与维持代价？
18. 对波是否写满五拍（蓄力、轰出、相遇、拉锯、反推/洞穿）？拉锯里弱势方有没有身体反应？是否停在相持不动？
19. 对轰是否同高度静止对推？是否至少一方在位移中施法？
20. 大型构造是否始终在施法者体外、朝向对手？有没有把施法者包在构造里？
21. 护体是否经历「凹陷 → 裂纹 → 破裂」？破裂后果是否延续到结尾？有没有一次消失或无限无敌？
22. 能力五项（来源、射程、形态、代价、失效）是否成立？一场是否只用 2–3 种形态？
23. 代价是否在最关键时刻发作并被看见？有没有无代价升级？

## 特效与色彩

24. 一场是否只有一套对立色？有没有每个技能换一种颜色？
25. 核心特效是否绑定命中、辅助特效是否绑定运动？有没有打完还亮着的「贴图光」？
26. 全屏光效是否都写了时长（≤1 秒）与收束方式？光爆中两人轮廓与接触点是否可读？
27. 技能余波是否只留焦痕、裂纹、碎屑？有没有残留发光法阵圈/光环被带进下一镜？
28. 能量染色天空是否 ≤1 秒、是否改变了环境底色？
29. 残影是否 2–3 道快速淡出？有没有变成分身？

## 冲击预算

30. 片型判断是否正确（写实收着打 / 一张一弛 / 全程高速）？配额是否按片型执行？
31. 冲击帧是否 ≤1 次（仅一张一弛）？hit-stop 是否 ≤2 次且每次 ≤0.15 秒？升格是否 ≤1 次且只覆盖命中瞬间？
32. 升格段是否只承载形变细节、位移是否全部在实时完成？
33. 升格前一镜是否交代了飞退方向有空场？

## 具体画面与节奏

34. 是否用「激烈打斗」「能量爆棚」「毁天灭地」等笼统评价代替动作？有则改成具体招式、回应与反馈。
35. 每格是否有可见状态推进，下一格是否从上一格的距离、重心和动作余势接出？
36. 每格信息是否可在半秒内表达？复杂动作应跨格延续，不一格堆整串独立招式。
37. 全程不停顿时是否误加对视、摆架势、喘息展示、冻结/AP 或静态结尾？
38. 用户要虚影时，是否让拳臂末端沿轨迹模糊，同时保留身体位置和受击结果？
39. 用户要手持时，是否写出摄影者步伐颠簸、转向侧倾和接触短震？

## 连续性与镜头

40. 剧情转译能回溯 E##/S##；原创编排的 B## 满足已定人物、能力、伤势上限、胜负及结局。
41. 人物左右、朝向、距离、空间轴线连续；起点、路径和落点都存在，不穿过未破实体。
42. 伤势、衣物、血迹、护体状态、能量余量、兵器状态、环境破坏是否连续？功能变化是否影响后续动作？
43. 0.5s 格不强制切镜。接触和第一拍反馈尽量同镜；每个切点延续动作方向、物件状态或结果。
44. 复合运镜名含定格/慢放而用户要求不停顿时，换兼容词条；不删其组成后仍冒称用了完整原词。
45. 光线方向、受光连续性：能量光照在脸上、地上、墙上的方向是否一致？
46. 声音顺序是否为「破风/充能 → 接触声+低频 → 余振 → 环境余响」？有没有先响后打？
47. 最终文本无内部编号、占位符、未确认假设；未生成视频时不声称成片效果已验证。

## 模式与授权

48. 是否清楚区分剧情转译与原创编排？转译模式是否误加未提供的反击、停顿、蓄力或能量升级？
49. 用户没有指定的能力是否被凭空加入（觉醒、飞行、瞬移、第二形态）？
50. 用户指定的结局、胜负、伤势上限是否被改动？

## 检查摘要

应简短：时序格数、使用的招式/能量/运镜原词出处、破坏推进到几级、能量形态与色系、主要连续性结果、尚未验证的成片效果。不要把整张检查表塞进提示词。

## 伤势检查

用户指定的骨折、伤口或少量流血是否被无必要地删成「毫发无伤」或含糊暗示？是否按 `pain-and-reaction.md` 简短直述结果、交代功能变化并保持血迹连续？超能者可以承受更大伤势而不失能，但不等于无伤。

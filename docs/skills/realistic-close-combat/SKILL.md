# 写实近身搏斗

## 核心职责

核心职责是把近身打斗设计成清楚、连续、可拍摄的动作与镜头。先判断用户要的是“按既定剧情转译”还是“创作/补全打戏”；允许用户自由设计招式时，可以原创动作编排，但仍须守住人物设定、武器、空间、胜负和结局等已给定条件。

按既定剧情转译时，用户提供的打戏剧情是唯一事件来源。人物、关系、动机、事件顺序、谁攻击谁、谁受伤、谁占优、谁逃脱、谁倒下、是否持械、武器如何出现和结局如何发生，全部以用户输入为准。

创作/补全打戏时，允许设计新的攻击、防守、假动作、反击、衔接和节奏变化；不把新招式当作新故事事件。不得擅自改变用户给定的人物关系、动机、武器归属、伤势上限、胜负、结局或指定事件。用户只给目标和约束、并明确把动作交给 Skill 设计时，不因缺少逐招脚本而追问；仅对会改变故事结果的关键歧义提问。若用户要求严格照已有剧情执行，则回到转译模式，不补招。

本 Skill 负责：

- 将事件拆成可拍摄的动作、反应、位移、镜头和声音。
- 将已有剧情事件安排到时间轴和镜头块中。
- 为徒手和持械接触补足力源、轨迹、接触点、身体反应和物件状态。
- 保持人物、武器、伤势、空间、光线、声音和破坏的连续性。
- 在不改剧情事件的前提下，让画面更清楚、更有重量、更容易被视频模型执行。

## 不得越界

在“按既定剧情转译”模式，不得自行添加或删除：

- 起因、前史、动机、心理活动、旁白、台词或新的信息。
- 新人物、新关系、新攻击、新反击、新伤势、新道具或新的环境事件。
- 用户没有指定的和解、停手、留手、误会、反转、逃脱或胜负改变。
- 为了“更真实”而改掉用户指定的结果、态势或人物能力。

用户只给了一个粗略打戏事件时：转译模式只能把同一事件拆成准备、接触、后果和连续性接口；创作模式可以在既定结果与授权范围内补充动作编排，并把新增动作标明为创作补足，便于用户审阅。

缺少会改变剧情或动作结果的信息时先询问，例如人物、人数、武器、事件顺序、关键接触/伤势、胜负和结局。时长、景别、焦段、机位、布光等制作参数可采用本 Skill 的默认值；要明确标出会影响结果的假设。若用户授权补充剧情缺项，再按授权范围补充并标明。

## 适用范围

适用于：

- 徒手近身搏斗、贴身控制、摔抱、推撞、逃脱和压制。
- 以近身接触为主、包含刀具、棍棒、撬棍、椅子或其他近距离物件的搏斗。
- 一对一、多人围攻、混战中的局部交手、狭窄通道和死路空间。
- 横屏、竖屏、多镜剪辑和用户明确要求的一镜到底。

不适用于：远程枪战、追车为主的动作、仙侠能量、超能力、机甲超英、纯武器技术教程或超出动作编排范围的完整故事创作。既定场景内的原创动作编排属于本 Skill 范围。

## 优先级

规则冲突时按以下顺序处理：

1. 用户明确给出的剧情、事件顺序、人物关系、动作结果和输出要求。
2. 本文件的写作硬规则、授权边界与连续性要求。
3. 适用的参考文件中的硬性连续性规则。
4. 参考文件中的默认倾向和风格建议。
5. 示例只用于展示写法，不构成剧情或参数默认值。

## 写作硬规则：具体画面、时序和词库

以下规则用于每次生成或修改打斗提示词，优先于下文的样片数值、镜长建议和旧示例。

1. **禁止笼统词代替画面**：成品不写「激烈打斗」「拳拳到肉」「火花四溅很爽」「高手对决」「高速、猛烈」等评价句来承担动作描述。把用户的情绪词转译为具体招式、轨迹、攻防回应、接触结果、身体反应和环境后果；不能只在总述里说快，再逐段复述同一评价。原生词条名称中已有的「极速」等字样可以保留，但仍须补出实际路径和覆盖时序，不能以保留原词为由省略执行描述。
2. **打斗逐 0.5s 规划并交付**：打斗段按 `0.0–0.5、0.5–1.0……` 连续列格；15s 纯打斗必须覆盖30格。成品动作时序也保留这些半秒格，不合并成1–2秒的模糊动作段。一个镜头可以连续覆盖多格，半秒格不等于半秒必切镜。总时长不是0.5s整数倍时，仅末格可以不足0.5s。
3. **剧情/对白用 2–3s 时序**：剧情向、对白向段落每2–3s一个时序块；和打斗混合时分别按类型规划，不用对白粒度稀释打斗。尾部不足时长按实际收束，不为凑格增加剧情。
4. **打斗默认持续加压**：所谓全程高燃、急速，要落实为逐格的出招—防守—命中/落空—位移—追击衔接。回收和下一招启动可以重叠；受击反应可以延续到下一格，不自动插入对视、摆架势、定格、喘息展示或静腔。用户指定停顿、对白、结果或严格转译时遵从用户；不能借此擅自补剧情。
5. **必须读取并使用本地库**：生成打斗前读取 `references/action-move-library.md`、`references/camera-move-library.md`、`references/chinese-action-writing.md`，再按需读其他资料。动作取招式库原词，镜头优先取运镜库原生术语及其七类分类。不得凭记忆声称已调用，也不得自造运镜名充当词条。
6. **取词后转为画面**：规划层确定招式原词；成品按当前阶段写清谁的哪部分怎样移动、对方如何回应、结果与接续。陌生术语不能代替动作特征，常见名称按需保留；复杂动作不能因去掉名称而退化成普通拳脚。持续动作可跨格，不逐格重写全链；每镜明确景别、运镜、机身状态与起点/路径/落点。具体写法与精简方法见 `references/chinese-action-writing.md`。
7. **可回溯**：规划表保留招式原词、ID、来源及其成品描述的对应关系；参考出处只放规划/检查层。成品移除内部ID与文件路径，以可见动作表达为主。用户仅要成品时仍完成逐格映射与连续性校验。
8. **库外缺项显式处理**：招式可在原词基础上编排变体，内部标为「原词＋变体」，不得假称库里已有；运镜若缺合适词条，使用库中基础运镜原词描述路径，不现编复合名称。用户明确要求扩库时才补新运镜词条。
9. **先编动作短语，再分时间格**：原创影视编排先确定连续组合的视觉变化和角色风格，再映射词库、分配半秒格。每格承载一个连续视觉任务，可包含有先后或重叠关系的多个动作，不能把“一个任务”误解为“只准一招”。角色主战族用于保持辨识度，不是阻止复杂组合的白名单。用户要求更快、更复杂或连招时，必须读取 `references/high-speed-screen-choreo.md`、连招库和高速贴身模式；不只替换形容词。

## 默认摄影与节奏基准

前述硬规则采用以下统一口径，模板与交付检查沿用，不另设相互冲突的限制：

- **成品词条口径**：所有动作采用“内部原词核对、成品可见描述”。名称仅作辅助，用户要求保留时补在描述旁；门派或动物意象转为可见身体运动。景别和运镜仍用库内基础术语并写路径。
- **重复检查**：检查连续画面是否重复，不按原词出现次数截断组合。相同原词在方向、节奏、回应或构图上有变化时可以连续使用；同一动作跨格只计延续。
- **配额范围**：参考中的族数、两次态势变化、两三拍连打等数字是普通风格建议，不是所有影视编排的硬上限。用户要求复杂高速组合时，按 `references/high-speed-screen-choreo.md` 处理；剧情、角色能力、空间与接触连续性仍是约束，不能为加速删掉必要过渡。
- **既定结尾优先**：用户指定的落地、停手或持续状态可以作为结尾，不受参考文件中“必须接后续动作”的泛化要求限制；不为续接动作而改变既定结果。

用户没有指定时，可把这张表作为制作参数参考。数值及其样本边界见 `references/rhythm-and-motion-baseline.md`。

| 项目 | 默认值 |
|---|---|
| 机身 / 高度 | 手持；1.4–1.7m（只有倒地或地面接触时才降到 0.3–0.6m） |
| 焦段 / 景别层级 | 近景与过肩为主体（50–85mm观感），运动中的手部/面部/接触特写用于关键拍点；只在腿法、大幅换位、失衡和空间关系需要证明时短暂拉到中景或全景（28–50mm观感），随后继续贴近 |
| 镜长 | 先逐0.5s安排动作，再按动作连续性合镜；短/长镜范围仅参考，不自动安排静腔 |
| 节奏 | 打斗每0.5s一格，连续动作贯穿镜头；默认不插静腔。剧情/对白每2–3s一块 |
| 速度 | 用户要求高速、暴力美学或未另行限制速度时，优先使用回收未完即启动下一招、防守与反击重叠、连续变线和脚步抢位呈现极快出招；拳、前臂与脚端带短促方向性运动模糊，躯干和落点仍可读。出拳等秒数仅为编排参数，不冒充实测或保证生成效果 |
| 重量 | 速度不能削弱力量感：接触后必须延续衣料受压、头肩偏转、躯干折叠、脚底滑移、攻击者自身惯性和重新支撑；末端运动模糊与身体反馈可并行。全程不停顿时冻结/AP为0 |
| 甩镜 | 默认 0 次。只有用户要求甩镜，或其指定的眩晕/失控需要主观镜头时才用，且 ≤ 1 次/15s |
| 镜头数 | 由事件数、动作可读性和时长决定；不为凑密度拆碎动作或增加招式 |
| 声音 | 只写动作直接产生的声音；不逐击加撞击音效，不自动配乐 |

这些是**风格参数**，不是剧情许可。它们决定"怎么拍"，不决定"谁打谁、谁赢、伤到哪里"。

### 高速、多招式与景别层级强化

用户要求“出拳极快”“力量感”“暴力美学”“招式丰富”“多种拳法和踢法”，或在原创编排中明确把招式设计交给 Skill 时，按以下规则强化；若用户指定克制、笨拙、单一流派、受伤受限或严格转译，则服从用户条件，不强行套用：

- **极快但可读**：速度来自前一招回收与下一招启动重叠、防守中反击、左右线路交替、上下来回变线和连续抢位。每个半秒格仍写清发起者、攻击线、对手回应和可见结果，不用“快到看不清”替代动作。
- **招式多样但有因果**：在距离和姿态允许时，从直线拳、弧线拳、近身肘膝、直线腿、横向腿、线路防守、躲闪、贴身控制与失衡动作中轮换取用。短片避免连续重复同一种拳或只写左右直拳；拳法与踢法都应出现，但每一招必须从上一拍的重心、距离和肢体位置自然接出，不能为凑数量堆成招式清单。
- **拳法覆盖**：可按动作目标组合刺拳、后手直拳、短直拳、摆拳、勾拳、短钩拳、挂捶、插捶、假刺拳和上下换线；至少让直线、弧线、假动作/变线三类在允许的原创高速段中形成变化。
- **踢法覆盖**：可按距离组合前踢、侧踹、低扫、侧踢、回旋踢、撩腿、跺子、挂腿、里合腿、反腿、膝撞或膝击；腿法前后必须交代支撑脚、骨盆方向、防守方式、落脚位置和下一拍接口。短时长不要求机械塞满所有踢法，优先保证不同作用线和清楚落点。
- **掌指与手型覆盖**：拳法之外可按目标取掌根推击、手刀劈击、标指、插掌、掌掴、抓面推压、凤眼插指、横哨扫掌；手型决定接触面积与后果，写清是面接触（推、压、掴）还是点接触（标指、插掌），不要把所有手掌动作写成同一种推。
- **控制与摔投覆盖**：用户授权或剧情需要接触控制时，可在抓腕、拍挡建立接触后接关节控制（抓腕反拧、折腕、别臂、压肘锁臂、正面锁颈）、投技（过肩摔、抱腿摔、接腿摔、大外刈、内股、出足扫、巴投）或失衡动作。抓控、破重心、摔出三拍缺一不可；摔完必须接压制、追击或起身，不得停在落地姿势。关节技与绞技只在用户剧情允许控制或降伏时取用，不得自行把交锋改成锁死结束或改变既定胜负。
- **地面段**：只在用户剧情允许倒地时进入，机位高度随之降到 0.3–0.6m；必须先交代谁在上、谁被压、哪只手自由，再写压制或挣脱。
- **器械动作覆盖**：先按 `action-move-library.md` 的「持械对决：三轴分类」定形态（短刃 / 短棍钝器 / 长杆 / 长刃）、对位关系与持械距离段，再从对应族取词。通用底层可取自正握捅刺、反握划割、劈砍、横砸、棍端戳击、器械互锁、夺刃控腕、出鞘、拨离、抽离、勾械卸械、换手、拾械、抵械僵持、弃械；形态专用词取自短刃技法、短棍钝器、长杆、长刃四族。
  - 每拍写出器物的具体部位（刃尖 / 刃口中段 / 刃根 / 刃背 / 棍端 / 棍尾 / 杆身）与轨迹（直刺 / 斜劈 / 横斩 / 上撩 / 下压），不写“挥刀攻击”。
  - 长度决定谁能打到谁：长度差超过一档时，短械方必须写出穿过空白区的过程，不能隔着一米半挥刃。
  - 持械段不套徒手四段距离，用测量距离 / 交刃距离 / 贴身压械三段；交刃相持最多两拍。
  - 握法确定后不得无声改变；同一段内不叠加完整的徒手拳击组合；转徒手须交代器械去向。
- **体系专用招式覆盖**：人物设定走南拳桥法、走转绕身、束展身法，或剧情需要有人从地面起身时，可取桥手接触（沉桥、架桥、提桥、撞桥、分桥、圈桥、穿桥、推桥、留桥、订桥、磨桥、制桥）、走转绕身（趟泥步、扣步、摆步、白蛇吐信、鹞子穿林、乌龙摆尾、狮子抱球、黑熊探掌、白猿托桃、金鸡抖翎、穿身绕掌、回身劈掌）、地趟起身（跌扑、滚地扫腿、倒地弹起、翻身踢、低姿勾弹、三角钉腿）与象形身法（马形冲撞、猴形束身、鹞形钻身、虎形扑按、燕形掠水）。这四族默认不进主战族，只有人物设定指定该打法时才整族启用；成品不写门派名与动物名，只写可拍的身体状态。桥法必须在一两拍内转成打击、控制或脱开，不得连续三拍只做桥法。
- **力量由后果交付**：快速命中后继续写 0.3–0.5 秒内的肩线旋转、躯干压缩、退步或横移、鞋底滑动、衣发延迟运动与攻击者自身前倾/收步。双方不得像无重量模型一样连续出招而身体毫无反馈。
- **方向性运动模糊**：拳头、前臂、脚端、头发与衣摆在最快阶段沿单一真实轨迹出现短促模糊；禁止复制肢体、光效残影、全屏糊化或用模糊跳过接触与落点。
- **近景主导**：大部分时长使用近景或过肩，让拳路、格挡、闪避和受击反馈同时处于画面内；特写必须发生在动作持续推进中，例如拍挡接触、抓腕旋转、拳头压紧衣料或脸侧擦过，不能变成静态眼神镜头。
- **偶尔拉远证明空间**：腿法、大幅换位、绊扫、摔撞、双方位置交换或环境碰撞前后，短暂连续拉至中景或全景，交代全身、支撑脚、人物关系和落点；信息建立后立即沿真实路径重新贴近，不长期停留宽景。
- **运镜跟交锋中心**：手持跟镜头或移镜头追踪双方躯干与共同位移，推镜头进入接触关系，拉镜头交代腿法与空间，水平/垂直摇镜头接住换向、下潜或起身。摄影机不逐拳乱追，不用每拳甩镜，接触时短震后继续原路径。

用户给出快速拳脚、连续命中、贴身跟拍或“拳拳到肉”等参考时，按需读取 `references/fast-impact-choreo.md`。该模式不改变用户固定的剧情条件；转译模式不新增事件，原创模式可在授权范围内设计并记录动作拍点。

## 输入整理

剧情转译模式先建立“剧情事件清单”，只记录用户说过的动作和结果；原创编排模式建立“动作拍点清单”，新增招式标为原创。人物仍站立、武器仍在手等状态约束单独记录，不要把状态写成新事件：

```text
E01 [时间或顺序] [人物] 对 [目标] 做 [用户指定动作]，结果是 [用户指定结果]
E02 [时间或顺序] [人物] 对 [目标] 做 [用户指定动作]，结果是 [用户指定结果]
...
```

另用 `S01...` 记录用户明确给出的状态约束。剧情转译模式的镜头标注来源事件 `E##` 或状态 `S##`；原创编排模式标注对应拍点 `B##` 及其满足的约束 `S##`。一个事件/拍点可以拆成多个镜头，但不得让一个镜头偷偷合并两个互不相关的事件。

先声明当前采用“剧情转译”或“原创编排”模式。剧情转译时建立事件清单，逐镜回溯用户事件；原创编排时建立“约束清单 + 动作拍点”，将固定条件与新增编排分开。若用户给出了对话或剧情段落，只负责把它们安排到时间轴，不能改写台词或补写信息，除非用户授权改写。对话段按 2–3 秒规划一格；打斗段按 0.5 秒规划并交付一格。两者可以相邻，但不要混用编号。

## 快速通道

用户只给一段 3–10 秒的短打戏、剧情已经清楚时，不必走完整工作流：

1. 转译模式列 `E01…E0n`，一句话一个既定事件；原创模式列 `B01…B0n` 并对照用户约束。
2. 读取招式与运镜库，按0.5s列完整动作时序；同镜可以覆盖多格，不默认插静腔。
3. 每镜写景别/焦段、机位高度和一个主要任务；有接触时写接触点与结果。
4. 普通接触写自然反应；末端运动虚影、身体反馈和手持受力可并行。全程不停顿时排除冻结/AP。
5. 按 B 骨架出成品提示词，`SHOT RHYTHM` 与 `IMPACT DELIVERY` 两行不能省。

完整工作流用于多场景、多人、长时长或需要严格连续性台账的任务。

## 统一工作流

### 1. 解析并确认边界

提取人物、关系、事件顺序、胜负或结局、时长、空间、退路、光线、武器和用户指定风格。缺项只问必要问题，不用默认剧情填空。

### 2. 建立事件账本

剧情转译模式把用户素材整理为 `E01...`；原创编排模式把授权内新编动作记为 `B01...` 并关联约束 `S01...`。同时建立状态账本：人物位置、朝向、手上物品、武器位置、伤势、衣物、环境破坏、光线和声音。状态变化必须能回溯到对应的既定事件或授权内动作拍点。

### 3. 选择时间粒度

- 打斗：以0.5秒为规划及交付时序格，逐格列出；同一镜头可覆盖多格，不强制切镜。
- 剧情或对白：2–3 秒是规划格；一句台词不自动等于一个格。
- 同一镜头可连续覆盖多个打斗格；格内可注明动作先后或短暂接触，但不得取消逐0.5s的交付边界。
- 镜数按事件复杂度、人数和可读性决定。不要为了达成固定镜数而增加动作或把一个接触切得不可读。
- 默认用连续交锋构成动作簇，以进攻线路、距离、攻守或空间转换区分段落；不靠静腔分隔。用户明确要求停顿或剧情本身包含停顿时才安排，并在规划层说明来源。

### 4. 把事件写成动作链

对每个用户事件或原创动作拍点，按适用部分写；下列环节按动作选用，不要求每项都出现：

```text
谁发起 → 力从哪里来 → 身体或武器走哪条线 → 接触点 → 受力形变
→ 失衡或控制结果 → 呼吸/声音 → 环境响应 → 下一事件接口
```

徒手动作写脚、髋、肩、肘、手、膝和重心，不靠门派名或空泛形容词。持械动作额外写握持手、武器朝向、刃/棍/物件的作用线、接触对象、脱手或卡住后的状态。不要把持械动作改写成徒手动作，也不要擅自增加武器攻击。

**按模式处理动作衔接。** 剧情转译模式保持用户给出的动作衔接，不擅自增加反击、追击、过渡动作或固定出招间隔。原创编排模式可设计攻防回应和过渡动作，但应符合距离、重心、反应时间、人物能力和器械状态；避免像招式清单一样互不相干地堆招。两种模式都不强制半秒内固定命中次数。打斗默认不加停顿；用户允许的迟疑、持续控制或结果停留才按其条件安排。

### 5. 设计镜头

每镜只承担一个主要视觉任务：一次接触、一个后果、一次位移、一个武器状态变化、一个环境响应或一个空间信息。一个事件可以跨镜，但切点必须清楚：

- **动作匹配**：优先沿未回收的运动方向切接，让下一镜接住相同动量；样片的完成百分比不是每次必切位置。
- **因果咬合**：接触完成后切到受击反应、武器脱手或环境后果。
- 接触帧和其后的位移尽量放在同一镜，避免切掉重量。
- 每一刀都写明“什么穿过切点”：动作线、视线、声音、物件状态或因果链。
- 运镜优先服务于人物和空间可读性；避免为了机械反向而无意义甩动。相邻镜头若同向，应说明它是在延续同一段位移或制造加速。
- **短镜只承载可读的动作拍点**：0.3–0.6 秒是参考值，不要求塞完发起、接触和反应。接触和关键后果若无法清楚同镜呈现，就延长镜头或拆到有因果关系的相邻镜头；不要为了符合镜长而切掉接触或硬加动作。
- **长镜服务于连续作用线或空间关系**：剧情转译可覆盖同一用户事件中的连续动作或已给出的持续状态；原创编排可覆盖同一动作链中的连续攻防。避免为制造控制权转移而无因补写抓、推、压制等动作。
- **快速连击可作为一个连续视觉任务**：剧情转译只呈现用户明确给出的连续出招；原创编排可按动作目标设计连续接触。若动作清楚且节奏适合，可在约 0.8–1.5s 的跟拍镜头里呈现 2–4 个接触拍点；该范围不是密度配额。每次接触仍要有明确落点和身体反馈。

以下为已登记的基础原词示例；生成前仍须读取 `references/camera-move-library.md`，不要只凭本表声称引用了完整词库。

| 原词/ID | 用途 | 执行要求 |
|---|---|---|
| 跟镜头 / MOVE-01 | 跟住双方共同位移 | 写跟随对象、路径、覆盖时序和落点；手持保留脚步颠簸 |
| 推镜头 / MOVE-02 | 随前压靠近接触关系 | 前送仅是幅度修饰，不能另造镜头名 |
| 移镜头 / MOVE-06 | 侧向或斜向跟住换位 | 保持攻击方向可追踪，写清摄影者路线 |
| 水平摇镜头 / MOVE-04 | 接住攻守转向 | 写动作触发、起止对象和落点 |
| 过肩 / LOCAL-03 | 构图交代双方关系 | 配近景或中景，不是独立运镜动作 |
| 甩镜 / LOCAL-01 | 特定动作触发的急转向 | 不每拳甩一次，模糊段不承担关键状态信息 |

### 6. 交付受击重量

普通接触呈现自然物理反应即可。肢体末端模糊、自然受击反馈与手持受力是不同层，可按需并行；冻结/AP等特殊强调不默认叠用。

1. **末端运动虚影**：拳、前臂和脚端可沿轨迹模糊，用户明确要快到虚影时不强制逐帧清晰；以躯干方向和接触后的身体反馈保持可读。
2. **受击位移**：命中只占 2–3 帧，重量交给随后 0.3–0.5 秒——退出原构图、退半个到一整个身位、脚离地、撞到墙或柱。
3. **冻结强调**：仅用户允许停顿时考虑；全程不停顿打斗禁止套用，不因旧样片出现就加入。
4. **AP 双锁**：同样仅在用户允许短暂停顿时选用，不能为增强冲击感压慢用户要求的连续交锋。

不用慢镜、冲击波、闪光、残影或特效震屏代替重量。不要把“飞出十米”当成每次重击的通用捷径；原创编排中的高潮可以适度腾空、飞移或撞击环境，但须有明确发力线和落地余势，并与普通命中拉开强度层级。重量也可以由**攻击者自己的失衡**承担：前倾、多走半步、被自己的动量带走。

### 7. 保持连续性

每个镜头交付前核对：

- 时间码无重叠、无空缺，总时长正确。
- 伤势、血迹、衣物、武器、道具和破坏只按事件发生改变，不会无故复原。
- 人物位置、朝向、距离、空间轴线和镜头高度连贯。
- 持械动作的武器始终有明确状态：握持、挥动、接触、卡住、掉落、被拿走或离开画面。
- 光线方向、曝光、声音层和残留物与前后镜头一致。
- 每个镜头的主要动作、景别、运镜和声音都服务于对应的 `E##` / `B##` 或 `S##`。

## 输出格式

内部完成A层规划与检查；默认向用户展示简短说明和B层完整提示词。用户只要提示词时省略说明；用户要求规划表、分镜或检查依据时再展示相应A层内容；用户明确只要规划时不附加B层。不要默认输出两套重复内容。

### 默认必须交付完整提示词

用户要求设计、编写、改写或补全打斗时，除非用户明确说“只要规划表”“只要分镜”“只要动作提纲”或指定其他单一格式，最终答复必须包含一份可直接复制到视频生成模型中的**完整成品提示词**，不能只交付动作表、创意说明、镜头摘要或提示词片段。

完整成品提示词必须满足：

- 使用下方 B 层的全部必要字段，正文写全场景、人物、空间、画幅/时长、光学与手持状态、连续运镜路径、动作时序、接触物理、连续性、光线、声音和正向约束。
- 纯打斗按 0.5 秒逐格写入 ACTION TIMING；15 秒必须在成品提示词内部完整保留 30 格，不得只在规划表中列出后再用“按上表执行”“连续交锋”等概括语替代。
- 一镜到底需求必须在提示词中明确写出：单个连续无剪切镜头、摄影机的起点/路径/景别变化/落点、节拍之间的连续连接，以及禁止切镜、瞬移、静态插入镜头。
- 用户要求近景、特写、偶尔拉远等景别变化时，把它们写成同一次连续摄影机运动中的推近、贴近、拉开或绕行，不把特写误写成剪辑插入镜头。
- 成品提示词使用自然、连续、可执行的语言；保留逐格时间码，但移除内部词条 ID、文件路径、事件编号和检查标记。
- 若用户只说“给我提示词”“写一段打斗”或提供场景后没有指定输出层级，默认同时给出简短说明和完整成品提示词，其中完整提示词是主要交付物。
- 如果篇幅受限，优先保留完整提示词和全部动作时序，压缩规划说明；不得以篇幅为由省略成品提示词。

### A. 动作与镜头规划表

此层默认内部使用，展示条件见上方输出规则。

先列逐0.5s动作表（含招式词条路径、具体回应、可见结果、伤势延续、下一格接口），再将连续动作格归入镜头；15s纯打斗先检查是否为30格。

```text
| 镜头 | 覆盖动作格/时间 | 时长 | 来源事件/状态 | 景别原词/焦段 | 机位高度 | 招式原词/词条路径 | 人物/武器状态 | 运镜原词/词条ID与路径 | 声音 | 切点接口 |
```

"时长"和"机位高度"必须填。声音、接触点等只在当前镜头适用时填写。

### B. 成品提示词

按目标模型选择结构，但至少覆盖以下信息。字段可合并为模板中的中文段落，不要求逐字保留英文标题；画幅、总时长、剪辑模式、焦段观感和机位高度必须明确，用户指定值优先。

```text
SCENE CONTEXT
CHARACTER / WEAPON ANCHORS
LOCATION AND SPATIAL BLOCKING
FORMAT MODE
OPTICS / CAMERA
SHOT RHYTHM
ACTION TIMING
PHYSICS AND CONTINUITY
IMPACT DELIVERY
LIGHTING
AUDIO
POSITIVE CONSTRAINTS
```

成品提示词只写摄影机看得见、麦克风听得到、并且来自用户剧情、原创编排授权或必要物理连续性的内容。不要把 `E01`、K/R/I/M/A 等内部标记直接投喂模型；它们可以留在规划表中。

## 默认写法

- **伤势直述**：用户剧情已指定或明确授权时，可以直接写“手臂骨折”“额角破口流血”“嘴角带血”，不必一律改成模糊暗示，也不把非血腥理解为完全无伤无血。以简短结果、疼痛反应与后续功能变化交代；镜头尺度与例句见 `references/pain-and-reaction.md` 的“伤势直述与特写”。未授权时不主动升级伤势。

- 受击反应比攻击动作更具体：写形变、脚步、呼吸、失衡和延迟反应。
- `fast`、`powerful`、`quickly` 不单独承担速度信息；给出时间、距离或画幅占比。
- 不用慢镜、冲击波、闪光、残影或特效震屏代替重量；夸张飞移只作为有铺垫、分级的高潮动作，不是每击的默认反馈。
- 破坏只有在用户剧情已有、或它是同一动作的直接物理后果时才出现。不要强制每场都添加破坏物。
- 持械场景优先保证武器、手、目标和作用线可读；不要用快速切镜掩盖武器连续性。握持方式（正握/反握）一旦确定，全段不得无声改变。
- 风格名称只在用户要求时转译为可见参数：光线、色彩、构图、镜头行为和材质。不要借风格名新增剧情元素。
- 不用甩镜、变速、大幅拖影或震屏代替清楚的动作表达。剧情转译模式的节奏来自用户事件；原创编排模式可设计动作密度与节奏，但必须留出接触反馈、位移和动作可读性所需的时间。
- 用竖直硬边（柱、门框、墙缝）做深度参照，让"退了两步"在画面上可测量。
- 人物的移动、头发、衣摆、裤脚要跟着动作甩起来；静止的衣物会让动作变成摆拍。
- 剧情转译模式不要自行添加停顿、对峙、独立反应、呼吸或收势；用户明确给出持续状态时，可以让镜头停留在该状态。原创编排模式可按动作因果设计必要的节奏拍和身体反应。

## 交付前硬检查

1. 剧情转译模式下，每个镜头是否能追溯到用户事件 `E##` 或明确状态 `S##`？原创编排模式下，新增动作是否在授权范围内并标记为创作补足？
2. 是否擅自改变人物关系、武器、伤势约束或结局？转译模式是否误加新事件？有就删除或询问。
3. 时间码是否完整，镜头是否为了“精彩”而塞入多个无关事件？
4. 人物、武器、伤势、道具和空间状态是否连续？
5. 每次接触是否写清作用线、接触点和受击结果？
6. 每个切点是否能说出有什么穿过去？
7. 运镜是否服务于动作和可读性，而不是机械执行方向交替？
8. 全程不停顿时是否把冻结/AP排除？用户允许时是否克制使用强调手段，而不是机械凑次数？
9. 镜头是否覆盖连续动作格，接触与结果能否衔接？镜长仅参考，不为符合范围硬拆动作。
10. **模式一致性**：是否清楚区分剧情转译和原创编排？转译模式是否把用户明确连续的动作拆散或补入未提供的反击、停顿、对视、喘息、准备动作？原创模式是否只在授权范围内补动作？
11. **节奏**：每个半秒格是否持续推进动作？是否误把半秒格当成切镜配额或命中配额？全程不停顿时是否仍夹入静腔或摆拍？
12. 机位高度、焦段在同一段落内是否稳定？跳变是否有物理原因？
13. 最终提示词是否已经移除内部编号、占位符、旧版术语和未确认的假设？
14. 纯打斗是否逐0.5s列满，总长15s是否30格？剧情/对白是否以2–3s块单独规划？
15. 是否实际读取词库，并让每个招式、景别、运镜有可核对原词出处？是否把自创镜头名伪装成库词？
16. 是否仍用笼统评价替代动作？每格是否有具体动作/状态推进与可见结果，而非只写「快」「狠」「连续对拆」？
17. 用户要虚影与手持时，是否保留肢体末端运动模糊、摄影者脚步/换向/受力晃动，而不是用全程清晰、稳定器或静态特写抵消要求？
18. **取词纪律**：动作是否符合距离？每格是否围绕一个连续视觉任务，格内动作的先后与重叠是否明确？是否把半秒格误当成单招时长，或用旧配额截断完整组合？
19. **连招是否有因果**：拍与拍之间能否说清上一拍的收尾姿态怎么接出下一拍？守方是否每击都有不同反应与步法位移，而不是三拍全部命中、对手全程配合挨打？
20. **表达与精简**：去掉招式名称后是否仍看得出不同动作？是否只删了重复说明，而保留全部时间格、复杂动作的中间过程、格内重叠关系和状态变化？成品与内部动作映射是否一致？

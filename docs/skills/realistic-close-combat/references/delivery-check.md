# 交付检查

生成前实际读取主文件、招式库、运镜库和中文写法。检查失败只修对应问题，不凭感觉宣称已经执行 Skill。需要连招或长段交锋时，另读 `references/combo-library.md` 与招式库里的“取词路由”。

## 时序与来源

1. 打斗逐0.5s列格，连续、无空缺/重叠且总长正确；15s纯打斗必须30格，只有非整倍数末格可不足0.5s。
2. 剧情/对白每2–3s一块，混合内容分别按类型规划，末段不足照实标注。
3. 每个攻击/防守动作引用招式库ID与原词；每镜景别、运镜引用运镜库ID与原词。库外动作变体明确标记，不虚构来源。
4. 规划保留原词与映射；成品以可见动作/路径为主，名称按需保留。去掉名称后仍应能辨别动作，不能只堆术语或自造运镜名。
5. 用户要完整提示词时，输出仍保留全部半秒动作格；用户只要成品时，内部完成引用检查，去掉文件路径和ID。

## 具体画面与节奏

6. 是否用「激烈打斗」「拳拳到肉」「火花四溅很爽」「高速、猛烈」等笼统评价代替动作？有则改成具体招式、回应与反馈。
7. 每格是否有可见状态推进，下一格是否从上一格的距离、重心和动作余势接出？不重复「双方对拆」填格。
8. 每格信息是否可在半秒内表达？复杂踢击、飞移、摔撞应跨格延续，不一格堆整串独立招式。
9. 全程不停顿时是否误加对视、摆架势、喘息展示、冻结/AP或静态结尾？快段不照搬旧样片静腔。
10. 用户要虚影时，是否让拳臂末端沿轨迹模糊，同时保留身体位置和受击结果？不能被全程清晰要求抵消。
11. 用户要手持时，是否写出摄影者步伐颠簸、转向侧倾和接触短震？不能被平滑稳定或仅微抖的默认值抵消。

## 连续性与镜头

12. 剧情转译能回溯E##/S##；原创编排的B##满足已定人物、武器、伤势上限、胜负及结局。不得把试写变成修改用户剧情。
13. 人物左右、朝向、距离、空间轴线连续；起点、路径和落点都存在，不穿过未破实体。
14. 伤势、衣物、血迹、物件、武器与环境破坏发生后持续保留，功能变化影响后续动作。
15. 持械状态连续；徒手场景不凭空拿东西；用库内投掷/穿越词条前验证场景条件。
16. 0.5s格不强制切镜。接触和第一拍反馈尽量同镜；每个切点延续动作方向、物件状态或结果。
17. 复合运镜名含定格/慢放而用户要求不停顿时，换兼容词条；不删其组成后仍冒称用了完整原词。
18. 普通命中有自然反应；高潮腾空/飞移有方向、落点和余势，不把夸张当错误或所有命中的默认尺度。
19. 光线、声音和尘屑连续；配乐、台词与额外音效按用户需求，不自动补剧情信息。
20. 最终文本无内部编号、占位符、未确认假设；未生成视频时不声称成片速度或运镜效果已验证。
21. 用户要求极快出招和力量感时，是否通过回收重叠、防守反击重叠、变线与抢位落实速度，并为命中补上持续身体反馈？不能只重复“极快”“有力量”。
22. 用户要求招式丰富时，是否在姿态与距离允许的前提下同时使用不同线路的拳法与踢法，并避免连续重复同一种直拳、同一种踢法或无因果堆招？
23. 是否保持近景/过肩为主要景别，让动作关系可读；动态特写是否仍有动作推进；中景/全景是否只在腿法、大幅换位、失衡或空间关系需要时短暂出现？
24. 拳、前臂和脚端的模糊是否沿真实运动方向短促出现，同时保留躯干、支撑脚、接触点与落点？是否排除了复制肢体、光效残影和全屏糊化？
25. 动作是否符合当前距离？每格是否围绕一个连续视觉任务，组合内多个动作是否说明先后与重叠？是否误把半秒当成单招时长，或用旧次数上限截断完整组合？
26. 连招拍与拍之间能否说清接口（上一拍收尾姿态如何接出下一拍）？是否准备了被挡与落空分支，还是三拍全命中、对手全程配合挨打？
27. 关节技、绞技、投技、地面动作是否在用户允许的范围内取用，没有擅自改成降伏结束或改变既定胜负？摔完是否接压制/追击/起身，没有停在落地姿势？
28. 用户指定了“像某人那样打”或某个打法时，是否按 `references/style-profiles.md` 定为某一档，并全程守同一档的主战族与节奏？是否取了该档的禁用词（例如截拳道型去抱摔、摔柔型去飞踢）？成品里是否没有出现人名、门派名或“某某式”的标签？
29. 持械段是否先定了形态（短刃 / 短棍钝器 / 长杆 / 长刃）与对位关系，再取词？每拍是否写出器物的具体部位与轨迹，而不是“挥刀攻击”“用棍打”？长度差超过一档时，短械方穿过空白区的过程是否写出来了？
30. 持械距离是否用的是测量 / 交刃 / 贴身压械三段，而不是徒手四段？交刃相持是否不超过两拍？器械状态（在手、哪只手、朝向、卡住、脱手、落地）是否全程可追溯，换手、拾械、弃械都有转换过程？持械段是否没有叠加完整拳击组合，或转徒手时交代了器械去向？

检查摘要应简短：时序格数、使用的招式/运镜原词出处、主要连续性结果、尚未验证的成片效果。不要把整张检查表重复塞进提示词。

伤势检查：用户指定的骨折、伤口或少量流血是否被无必要地删成“毫发无伤”或含糊暗示？是否按 `pain-and-reaction.md` 简短直述结果、交代功能变化并保持血迹连续？是否避免露骨伤口和断骨过程特写，且没有擅自升级伤势或为展示伤势打断连续动作？

高速复杂需求增加检查：是否先组织完整组合再分格；去掉速度形容词后能否仍看出快速接续；是否安排了有完整进入与退出的复杂动作亮点；受击反馈是否与后续表演并行；摄影是否容纳全身路径。具体标准见 `high-speed-screen-choreo.md`，不得用文字检查冒充出片验证。

输出核对：默认只展示简短说明与完整成品，A层按用户请求展示。成品须明确画幅、总时长、剪辑模式、焦段观感和机位高度；一镜到底须有连续路径。动作按主文件的成品词条口径转译，内部保留原词与映射。删重复信息后核对时序、动作过程、接续和状态变化未遗漏。测试或评审请求不自动授权修改Skill文件。

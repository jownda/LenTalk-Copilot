> 状态：P0 / P1 已实现并验证（tsc / 141 项测试 / build 通过），P2 起按阶段继续  
> 对齐来源：Cully Hill Boys — Project Brief.docx、CINEDANCE HIGGSFIELD SKILL.md、表演技巧 ACTING SKILL.md、V2 优化文档、最终审计计划  

## 1. 当前结论

最新导出的提示词属于「结构合格、执行冗余」的草稿，不是最终生成版本。主要问题按优先级排列：

1. **缺少第一段「场景语境」**。最终提示词直接从活动引用开始，与 Brief 要求的「每一段先讲清楚发生了什么、有谁、拍多久」不一致。
2. **活动引用存在 raw ID 泄漏**。道具输出成了 `@prop_... [image3]：prop_rycz_...；道具默认：持有者...`，第二个位置直接输出了内部 ID。
3. **身份锚重复**。角色完整描述后面又整段重复身份锚，同一批服装/发型词连续出现两次。
4. **镜头执行三层重复**。表演基调、镜头眼神、按角色分块的节拍在说同一件事，信息没有合并。
5. **音频尾巴与结尾死寂冲突**。规则写「每句对白后保留 0.5–1 秒尾巴」，但镜头 3 又说进入短暂死寂，缺少例外说明。

## 2. 必须补：场景语境（P0）

### 2.1 它是什么

场景语境不等于「前情提要」，也不是把用户填的“前情续接 / 故事梗概”原文搬进来。它是当前这个片段本身的戏剧事实：

```text
场景语境：
场景 01，全长 15 秒。三名角色已入画：阿俊擦开车窗雾气后看见窗外只有黑暗，
琪琪抱紧红色公文包，黛莲双手压住腿上的托特包。
```

### 2.2 内容公式

每个场景语境必须回答：

1. 当前片段是什么，总时长多少。
2. 在哪里、什么时间/天气/年代（如果设置了）。
3. 谁在画面内。
4. 第一帧正在发生什么戏剧动作。
5. 这段的核心冲突或悬念是什么。

### 2.3 硬规则

- 必须是最终提示词第一段。
- 中文界面只输出中文；英文界面只输出英文。
- 不超过 3 个句子，15 秒内的短片段尽量压到 1–2 句。
- 不得出现：前情提要、上集回顾、用户备注、AI 编译说明、连续性警告、镜头检查信息。
- 场景语境内只写角色显示名，`@tag` 与 `[imageN]` 全部留给活动引用。

### 2.4 落地方式

1. AI schema 顶层增加 `sceneContext: string`，由 AI 在编译时生成。
2. `SceneV02` 增加可选 `sceneContext?: string`，中文界面保存中文、英文界面保存英文。
3. 渲染器新增 `renderSceneContext()`：
   - 优先使用 AI 生成的 `sceneContext`，通过 sanitizer 校验后输出；
   - AI 未生成时，从结构化数据确定性回退：场景名 + 总时长 + 地点/时间/天气 + 首帧参与资产 + 第一个可见节拍；
   - 回退文本不允许使用用户前情/故事梗概原文。
4. 最终审计新增：
   - `SCENE.CONTEXT_MISSING`：缺少场景语境；
   - `SCENE.CONTEXT_META_LEAK`：出现前情/AI 说明/警告等元信息；
   - `SCENE.CONTEXT_TOO_LONG`：超过 3 个句子。

## 3. Brief 里可吸收的官方规则

| Brief 规则 | 在项目里的落地 |
| --- | --- |
| 每一段先写发生了什么、有谁、拍多久 | 补场景语境，作为固定第一段 |
| 资产第一：角色/地点/道具先锁定、命名、版本化 | 活动引用只输出当前镜头实际使用的资产，同一 `@tag` 全局只出现一次 |
| 每一次都写完整描述，不缩写 | 完整可见身份描述保留在活动引用，正文使用角色名，不重复整段服装清单 |
| 年代是规则不是装饰 | 场景设置明确了年代/时间/天气时，场景语境与地点描述中持续出现，不进负面词 |
| 复杂动作不能放在时间轴中间 | 镜头 1 的开头节拍直接写中动作状态，例如“已经形成中动作”，而不是“先走过去再慢慢抬手” |
| 每镜头一套镜头语言 | 长镜头统一 FOV 与机位；多镜头只能在切点变更 FOV，同一镜内不得静默变化 |
| 给模型更少的自由度 | 正向约束写可见证明：接触阴影、道具接触点、物体数量、身体朝向，代替情绪形容词 |
| 默认 SFX only，无音乐 | 默认无配乐、无字幕，只有环境声与画面同步发生的物理声音；用户显式选择后才出现音乐/字幕 |
| 版本化提示词库 | 与 Brief 的 prompt library 一致：每次编译保留结构快照，避免整体重写 |

### P2 镜头执行合并

1. 每镜头只保留一个块：时间范围 + 节拍 + 切点。
2. 节拍格式固定为：`角色：动作（对象）→ 可见变化；提前反应者单独一行`。
3. 删除“表演基调/镜头眼神/角色分组”三层结构性重复。
4. 对白前反应必须挂在反应者名下，不写进说话者的节拍。

### P3 音频规则收口

1. 定义三种结尾：普通对白尾巴 0.5–1 秒；抢话 0.3 秒内插入；死寂必须在音频段显式声明。
2. 音频段先写默认环境声，再写用户选择的音乐/字幕。

### P4 Brief 专项

1. 场景信息增加可选 `period`（年代/年代约束），进入场景语境与地点描述。
2. 复杂动作开头节拍支持“已处于中动作状态”表达式。
3. 地点描述中，“诡异/空旷”等氛围词必须转成可观察事实。

### P5 最终审计

1. 检查输出第一段、活动引用唯一性、身份锚重复、音频结尾规则、镜头时长总和。
2. 审计冲突在最终输出前处理，审计结果不进入提示词文本。

## 8. 明确不做的事

- 不把用户前情/故事梗概原文输出到最终提示词。
- 不输出表演评分、连续性警告、AI 编译说明。
- 不默认添加配乐或字幕，除非用户在音频计划中显式选择。
- AI 不回写用户音频计划；只把音频计划作为理解参考。
- 风格/全局技术默认不进入最终提示词，除非用户主动锁定风格资产或风格配方。

## 实施记录

### 已完成：P0 核心路径

1. 最终编译器只从结构化场景、镜头和资产重建输出，不再原样透传 `directorLayers` 或镜头检查器文本。
2. `ACTIVE REFERENCES` 全局只保留一次 `@资产` 引用；镜头正文改用普通名称，避免重复资产卡与图片序号漂移。
3. 时间轴会被归一为一条连续墙钟时间线；长镜头中的旧分段会自动合并为连续节拍，只有超时等真实事实冲突才会阻断导出。
4. 多镜头在动作时序内明确写出硬切、动作匹配剪辑或声音/动作重叠；缺失切点时默认硬切会进入审计记录。
5. 当角色的左/右屏幕位置和“向相反方向移动到该角色”的镜头指令同时明确时，连续性引擎会报阻断错误并说明字段来源。
6. 最终输出不再包含评分、检查器标题、连续性诊断、资产用途/忽略项和前情提要；中文导出的固定场景地图标签已统一为中文。
7. 编辑器顶部最终审计状态现在汇总最终审计和连续性阻断项，阻断时禁止复制、TXT/Markdown 导出和发送到视频节点。

### 已完成：P1/P2 最终审计层

1. “窗外绝对黑”与同一场景中明确可见的窗外霓虹/街灯并存时，最终审计会阻断并标明两个冲突来源。
2. 最终输出新增 `角色表演` 层，保留表演描述、眼神、节拍变化和台词结束前反应；评分、潜台词和策略等检查器元数据不会导出。
3. 内置的身份漂移、服装变化、多余肢体、无重力、漂浮道具、文字/水印失败模式，已按所属位置改写成正向可见锁；未知的用户自由文本不擅自转换。
4. 最终审计会将确定性的光学冲突组合自动规范：广角（如 `84°`）搭配“压缩感”会改写为“纵深拉开，近景略大于远景”；长焦/短长焦（如 `29°`）搭配“近大远小”会改写为“背景压缩，人物比例自然”。这里列举的是**冲突组合**，不是光学效果的归因说明。
5. 仅含“恐惧/愤怒/紧张”等抽象情绪、而没有可见动作的表演会提示补充；开口角色没有声音锁会提示并定位至对应镜头。最终声音段只输出实际对白顺序和角色声音锁，不导出用户音频计划原文。
6. 编辑器可展开查看自动修正与待处理问题，阻断/警告可定位至场景简报或镜头检查器；每次 AI 编译和本地编译的审计结果都会写入工程内的审计变更记录。
7. 最终渲染先构建仅含可导出字段的 `FinalPromptDocument`；评分、检查器备注和 AI 分层原文不会进入该中间模型。多镜头逐镜导出 `FOV + 可见结果`，长镜头只使用第一套相机/FOV，并保留连续的动作节拍。
8. 最终声音层默认保留真实的场景环境声和动作同步声，同时默认“无配乐、无字幕”；用户在音频计划中主动选择后，才附加画内音乐、环境音效、原始配乐或烧录字幕。

当前回归覆盖：时间轴归一、超时、长镜头模式冲突、缺失切点默认值、一次资产引用、未参与角色泄漏、切点输出、中文场景地图和目标方向冲突。

### 最终审核运行方式（本次调整）

1. 先从当前结构化场景重建最终提示词，检查是否符合本文的整体骨架、语言、拍摄模式、资产引用和时间线规则；不回读旧草稿的局部错误来重复追责。
2. 可确定的旧格式问题，例如时间从零重置、缺失切点、长镜头遗留多个分段，会自动整理并记录为提示，不阻断用户继续。
3. 只有无法同时成立的事实冲突才阻断，例如超时、明确的左右方向相反、窗外完全黑暗却要求可见窗外霓虹。
4. 用户在场景、镜头或资产数据中修正冲突后，点击编辑器审核状态旁的“修正后继续生成”，系统会以修正后的当前数据重新生成最终提示词并再次审核。

### 时长与长镜头硬规则（本次确认）

1. 用户设置的场景时长是最终提示词的硬上限。多镜头的总秒数必须小于或等于该值；超过上限的 AI 草案只能作为可编辑分镜，不得覆盖最后一次有效提示词，也不能复制、导出或发送。
2. 多镜头数量由剧情节奏决定，不按模板凑数。慢节奏、观察或对话场景通常只需要 1–3 个镜头；只有信息、动作或情绪发生清晰变化时才新增镜头。
3. 长镜头严格是一镜到底：AI 只返回一个镜头，所有叙事推进放入该镜头的连续节拍；旧项目遗留的多个分段在导出时合并为一个连续时间轴，不输出切点或多套机位。
4. 上述规则在点击“AI编译提示词”的规划阶段就执行：AI 收到明确的时长、节奏和长镜头约束；返回结果会再次校验，超时规划不会应用到场景，长镜头的额外覆盖镜头会被忽略。

### 简报 AI 优化填写

1. 时长输入框旁的“AI优化填写”只补齐必须发生、禁止发生、对白、情绪走向、表演目标和音频计划。
2. 该操作不生成镜头、不生成导演文档、不覆盖提示词编辑器，也不触发最终审计。
3. 上述字段标记为“仅作 AI 参考”：后续 AI 分镜会读取它们，但不会由 AI 擅自改写或新增音频计划。最终导出默认明确“无配乐、无字幕”，但始终保留与地点/天气一致的环境底噪，以及随可见动作发生的呼吸、衣料、脚步、道具接触、摩擦和碰撞声；只有用户主动选择画内音乐、额外环境音效、原始配乐或字幕时，才导出相应的附加指令。

## 1. 目标与边界

### 1.1 目标

最终提示词必须是可直接提交给视频模型的**导演指令**，而不是 UI 表单、检查器、AI 推理过程或镜头数据库的逐行导出。

最终输出应满足以下条件：

1. 一个清晰的拍摄模式，不同时声称「长镜头」和「多镜头」。
2. 一条不重叠的总时间轴，且总时长不超过用户/项目设置的上限。
3. 每个 `@资产` 只在 `ACTIVE REFERENCES` 中出现一次；后续用角色名或代词指代。
4. 空间关系、屏幕方向、机位侧、人物移动方向不互相矛盾。
5. 每个镜头只携带对该镜可见或声音上必须存在的角色与道具。
6. 每个镜头只有一套可执行的光学、机位、动作、表演和声音指令。
7. 输出不含评分、检查结果、资产用途/忽略项、启用状态、版本记录、AI 备注或空段。
8. 中文界面输出中文，英文界面输出英文；`@资产名`、FOV、SFX 等平台/技术固定名词允许保留。

### 1.2 不做的事

最终审计层不是第二个自由创作 AI。它不得：

1. 改写用户已经确认的剧情事实、台词、角色身份、资产或时代设定。
2. 擅自把用户选择的「长镜头」改成「多镜头」，或反向修改。
3. 猜测左/右、人物位置、窗外内容等无法由结构化数据唯一确定的事实。
4. 为了通过检查而删除关键剧情动作。

语义无法唯一裁决时，审计层必须回到结构化场景数据重新编译；若数据本身仍冲突，则在检查面板指出冲突字段，不能静默输出看似完整但自相矛盾的提示词。

## 3. 最终输出的权威数据

审计层不得以 `directorLayers` 的自由文本作为唯一真相。权威顺序如下：

1. 用户显式设置：语言、目标平台、最大时长、长镜头/多镜头、锁定层。
2. 结构化场景数据：地点、人物站位、镜头 participants、节拍、对白、道具状态、FOV、相机、声音锁。
3. 资产库：资产 ID、名称、锁定身份锚、地点几何与材质。
4. AI 分层文本：只作为润色素材；与 1–3 冲突时不得覆盖它们。

### 3.1 固定输出骨架

最终输出不强制填满每一块，但顺序固定。空块直接省略。

```text
场景语境
活动引用
场景地图与首帧
格式模式
光学与摄影机
动作时序
物理与材质
灯光与曝光
声音
角色表演
风格与质量
局部正向锁
```

英文界面使用对应英文标题。标题之后始终保留中文/英文的冒号，不使用无分隔的散文堆叠。

### 3.2 模式硬规则

| 模式 | 允许内容 | 禁止内容 |
|---|---|---|
| 长镜头 | 一个连续摄影机方案；一条连续时间轴；1–8 个行为节拍 | `CUT`、多套 FOV、多套机位、重置人物站位 |
| 多镜头 | 1–8 个编号镜头；每镜独立 FOV/机位；所有切点和全局起止时间清晰 | 隐性跳切、每镜从 0 秒重新计时、无切点的机位突变 |

若用户选择长镜头而 AI 生成多个镜头，不能直接拼接原文。应由结构化数据重组为单一镜头，或要求 AI 重新编译成同一摄影机下的连续节拍。

若用户选择多镜头而 AI 未指定切点，审计层应把镜头边界转为明确 `HARD CUT` / `CUT ON ACTION` / `WHIP PAN` 之一；没有可判定边界时，标记为阻断错误并重新编译。

## 4. 分阶段纠错步骤

每一步完成后必须增加测试，再进入下一步。不要把所有规则一次性塞进 AI prompt。

### P0.1 建立最终输出中间模型

**目的**：先把「可导出内容」和「编辑器元数据」分开。

1. 新建 `FinalPromptDocument`，包含 locale、formatMode、duration、activeReferences、locationMap、firstFrame、shots、physics、lighting、audio、style、localLocks。
2. `ShotDocument` 只保留：编号、全局起止时间、可见/声源资产、站位、FOV、相机、节拍、对白、可拍摄表演、声音。
3. 明确排除：`performanceLevel`、连续性 warning/error、资产用途/忽略项、资产版本记录、用户备注、AI 编译说明、镜头检查文本标签。
4. `directorLayers` 先解析为候选文本，不能直接写入提示词编辑器。

**验收**：给任一旧项目加载后，能生成中间模型；不包含诊断或 UI 字段。

### P0.2 统一活动引用与身份锚

**目的**：防止重复标签、错位图片序号和不在场角色泄漏。

1. 从地点资产、每镜 participants、对白声源、节拍目标、道具状态收集资产 ID。
2. 用资产 ID 去重并按地点、角色、道具稳定排序。
3. 只在 `活动引用` 区输出一次 `@tag` 与最小身份锚；地点明确「只控制几何、材质、光线和氛围，不控制取景」。
4. 镜头内只写角色名；只有画外声音角色可在该镜补「画外声音：角色名」。
5. 未被收集的资产名、`启用/未启用`、`用途/忽略`、`[imageN]` 都从最终输出清除。

**验收**：同一 `@tag` 计数恰为 1；每镜引用均属于全局活动引用集合。

### P0.3 先校验模式，再生成时间轴

**目的**：杜绝“长镜头 + 多机位”和超时。

1. 读取用户选择的 `shootingMode` 与最大时长；最大时长缺失时以项目默认值为准。
2. 长镜头：合并为一段 `0:00–总时长`，保留连续节拍，统一 FOV、摄影机、机位侧和屏幕轴线。
3. 多镜头：按镜头时长重新累计为不重叠全局时间，生成 `镜头 1：0:00–0:03` 等格式。
4. 总时长超过上限时，先删空镜/重复反应，再压缩停顿；仍超限则进入「需要重新分镜」，不得截断最后一句台词。
5. 末句对白后默认保留 0.5–1.0 秒可剪辑尾巴，除非用户指定立即切断。

**验收**：任意两个镜头无时间重叠；最后结束时间不大于最大时长；格式模式和镜头数一致。

### P0.4 建立空间、轴线与方向校验

**目的**：让地铁对话、正反打和摇镜不越轴、不移动到错误的人。

1. 将地点、人物、道具转成内部空间地图：摄影机位置/朝向、前中后景、左右座椅、主体位置、移动路径、主要光源。
2. 给每镜记录 `screenSide`、`cameraSide`、`bodyFacing`、`gazeTarget`、`movementDirection`。
3. 检查「目标人物屏幕位置」和「摄影机横移/摇移方向」：例如目标在左，`向右移到目标` 为 error。
4. 检查相邻镜头的 180 度轴线。允许跨轴时必须有明显的轴线重建镜头或明确动机。
5. 将首帧写成可验证句：第一帧已有谁、谁不可见、谁在何处、不可出现何种未指定内容。

**验收**：每镜均有可读的首帧和空间关系；任何方向冲突都显示字段来源，不能被静默忽略。

### P0.5 导出净化器

**目的**：从根源上消除“镜头数据导出”的阅读感。

1. 删除检查器标题、评分、`镜头检查`、`角色站位（从左到右）` 等内部标签。
2. 合并重复资产段、重复站位句、重复身份锚和重复风格句。
3. 删除前情提要原文；只保留与本镜可见动作直接相关的一句场景语境。
4. 删除空块、连续空行和无内容的「备注」。
5. 输出术语按 locale 统一；中文输出不能混入完整英文资产描述，英文输出不能混入完整中文说明。

**验收**：提示词编辑器中的文本可以从头读到尾，且没有任何“系统正在检查/导出字段”的语气。

### P1.1 光学与摄影机一致性

1. FOV 是唯一光学语义字段；镜头品牌只作可选实现细节。
2. 每镜用「FOV + 可见结果」表达，例如 `84° 广角，车厢纵深拉开，近景略大于远景`。
3. 多镜头变更 FOV 时，必须在切点后生效；长镜头不得变更 FOV。
4. 47° 建立全景和大特写可共用同一镜头，但必须写成物理推近，不能被当作静态镜位。
5. 将**冲突组合** `广角 + 压缩感`、`长焦 + 近大远小` 自动替换为规范表述。长焦产生背景压缩是正确效果；冲突在于把“近大远小”的广角透视结果错误地写给长焦。

**验收**：每镜一套 FOV/机位；不会同时出现与该 FOV 相反的光学结果。

### P1.2 灯光、物理与地点事实一致性

1. 灯光层从场景地图读取主光、方向、曝光优先级和允许高光。
2. 可见的窗外内容、光源与天气必须一致：若窗外是绝对黑，则不能同时要求可见霓虹/街灯；若有霓虹，必须说明它如何穿透车窗进入画面。
3. 物理层只保留当前场景需要的锚：地铁振动、车窗雾气、衣料随呼吸、扶手接触阴影等。
4. 禁止把每镜都机械附加「灰尘漂浮」等万能粒子。

**验收**：每个光源都可在地点/画面中找到；物理锚与动作、天气和空间相符。

### P1.3 表演与声音转为可拍摄事件

1. 对画面内每个主要角色补齐：动词目标、阻碍、失败代价、当前策略、可见身体业务。
2. 将抽象情绪词改成可见行为。例如「恐惧加剧」改为「她听到关键词时先停住擦雾的手，呼吸停半拍，再把手指收紧」。
3. 反应必须发生在伙伴台词结束前或紧接其后；多人反应按波次错开，不能齐刷刷同一表情。
4. 近景只保留眼动、眨眼、呼吸、嘴角和极小姿势变化，避免全脸夸张表情。
5. 开口角色必须粘贴对应声音锁；静默角色不重复声音锁。
6. 声音层明确：谁说话、打断点、环境声、是否配乐、是否字幕，以及对白结束后的声音尾巴。

**验收**：每句表演都能被摄影机拍到；没有只写“害怕/愤怒/紧张”而没有行为的句子。

### P1.4 局部锁替代全局负面块

1. 删除默认大段 `NEGATIVE LOCKS (GLOBAL ONLY)`。
2. 仅对已发生过的具体失败写局部正向锁：对象、位置、数量、可见证据。
3. 示例：不要写「黑色不深邃」，写「车窗外持续是无灯、无建筑轮廓、无站台元素的深黑」。
4. 身份锁只在活动引用中完整出现一次；镜头正文不重复衣物和脸部清单。

**验收**：没有泛化禁止词堆；每条锁都能指出防止的具体失败画面。

### P2.1 最终审计层的运行顺序

```text
结构化场景数据 + AI 分层文本
  -> 生成 FinalPromptDocument
  -> P0 确定性检查与格式修正
  -> P1 一致性检查与局部重组
  -> P2 文案密度与 locale 净化
  -> 再验证
  -> 通过：写入提示词编辑器
  -> 未通过：结构化回退或要求重新 AI 编译
```

审计层应在「AI 编译提示词」和「本地编译」两条路径共用。本地编译没有 AI 分层文本，也必须经过时间轴、引用、净化和冲突检查。

### P2.2 自动修复与人工决策的边界

| 类别 | 例子 | 处理 |
|---|---|---|
| 可确定格式问题 | 空标题、重复空行、评分、诊断字段、重复 `@tag` | 自动清除/合并，并记录审计日志 |
| 可确定结构问题 | 多镜头时间从 0 重置、镜头超出全局上限、长镜头多套相机 | 从结构化镜头重新编排；无法重排则阻断并重新编译 |
| 词汇冲突 | 84° + 压缩感、29° + 近大远小 | 自动替换为 FOV 词库的对应可见结果 |
| 事实冲突 | 人物在左却要求向右移到该人物；绝对黑窗外却有可见霓虹 | 阻断该镜；显示冲突字段和来源，不能猜测修正 |
| 内容缺失 | 开口角色无声音锁、镜头无首帧、无动作节拍 | 用结构化数据补齐；结构化也缺失时标记为需重新 AI 编译 |

### P2.3 审计结果 UI

1. 提示词编辑器上方显示简洁状态：`已通过最终审计`、`已自动修正 N 项` 或 `存在 N 个必须修正的问题`。
2. 自动修正可展开查看前后差异，但不把日志写入最终提示词。
3. 阻断问题显示镜头号、字段、冲突的两句话和推荐操作：`返回场景地图`、`重新 AI 编译`、`改为多镜头`。
4. 用户可以查看原始 AI 草稿，但“发送到视频节点”和复制默认只使用审计通过的版本。
5. 所有审计结果进入项目变更记录，便于复现某一次成功生成。

## 6. 必须新增的回归样本

### 样本 A：无尽地铁三人对话（本次问题复现）

输入：黛莲左、阿俊中、琪琪右；阿俊讲传说；黛莲抢话；最大 15 秒；多镜头。

期望：

1. 总时长不超过 15 秒。
2. 输出为受控多镜头，具有 3–4 个全局时间段与明确切点。
3. 四个活动引用最多各出现一次；后续不再有 `[imageN]`。
4. 镜头内角色集合与实际可见/画外声源一致。
5. 黛莲若在屏幕左侧，最终摇镜/横移方向与目标位置一致。
6. 窗外只允许一种可见事实：绝对黑，或带明确来源的城市光；不能并存。
7. 输出不含表演评分、连续性摘要、资产用途/忽略项、全局负面词堆。

### 样本 B：长镜头单人走廊

输入：长镜头、8 秒、一个角色、一个地点。

期望：一套 FOV、一套摄影机、一条 0:00–0:08 时间轴、无 `CUT`、无第二镜头标题。

### 样本 C：多镜头正反打

输入：多镜头、12 秒、两人对话、明确 180 度轴线。

期望：每镜切点清晰；正反打不越轴；反应在对方台词结束前开始；每位说话人只使用自己的声音锁。

### 样本 D：事实冲突

输入：人物站位在左，镜头指令要求向右移到该人物；或窗外绝对黑但灯光层要求可见霓虹。

期望：审计状态为阻断，不生成伪修正文本；UI 指向冲突字段。

## 7. 完成定义

此专项完成时，用户在提示词编辑器看到的文本应当：

1. 读起来像一份简洁、连续、可拍摄的导演提示词。
2. 不再像包含「镜头检查」「用途」「评分」「备注」的数据库导出。
3. 任意一段都能回答：谁在画面里、在哪里、第一帧是什么、镜头如何移动、什么时候切、谁在何时说话。
4. 不会同时要求模型执行互斥的时长、镜头模式、空间方向、光学结果或灯光事实。
5. 所有自动修改可追溯，所有无法安全判断的冲突都明确暴露给用户。
